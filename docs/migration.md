## CI and release boundaries

This public policy targets `Digifender-LLC/whumpo-mobile` (GitHub repository ID
`1446445212`).

This follow-up adds public `CI` and `Android` workflow definitions for every pull
request and `main` push. They use read-only permissions and isolated
`ubuntu-24.04` hosted runners, with no repository secrets, signing, provider calls
or backend access. The five source-defined check names are:

- `Mobile policy`
- `Secret scan`
- `Assemble, lint and unit tests`
- `Instrumented tests (API 28)`
- `Instrumented tests (API 36)`

Definitions in source are not evidence of a run or of required branch-protection
settings. This packet does not edit repository settings or transfer website
ownership; private website gates remain unchanged. Client instrumentation excludes
the private `WorkerJourneyTest`, which remains a separate website integration
requirement and is not replaced by these client checks.

The separate trusted-main merge controller is implemented in source; installation
requires its separately reviewed bootstrap. Until then, the existing external hourly
coordination path remains the fallback; unavailable event-driven automation is a
bootstrap/infrastructure limitation, not a new owner-approval requirement. Do not
use native queued auto-merge, bypass protection or create a public-PR runner
exception. An unchanged hosted Actions billing or runner refusal is an
infrastructure blocker, not a source failure; do not retry it unchanged or change
settings to work around it.

Controller bootstrap requires a saved ruleset with the five exact checks bound
to GitHub Actions app ID `15368` as their required status-check source, and
successful runs for all five from that source. This is a technical readiness
condition, not a new owner-permission loop; this packet does not change ruleset
settings.

The controller only merges same-repository, non-fork, non-draft code
PRs, with advisory reviews and no human approval quota or sensitive-path exclusion.
It must require all five checks to pass for the exact current PR head and base,
resolved review threads, and two fresh reads that detect head/base/status races.
For `pull_request` runs, associate evidence with the run `head_sha` and attached
PR head/base; the checkout is GitHub's synthetic merge result, not a raw-head
checkout. The controller must reject stale base or check evidence.
Protections must require the checks with GitHub Actions app ID `15368` as their
status-check source, allow zero human approvals, and disallow deletion and
non-fast-forward updates. The app ID is the required-check source, not a merge
actor. Do not use a bypass guard or native queued auto-merge. Use one writer per
branch and cap bounded retries at three. Its implementation makes no mutation
retries and fails closed on unknown outcomes. See the
[merge policy](agent-merge-policy.md) for the no-checkout review signal, read-only
manual inspection and trusted-main write boundary. Source/synthetic test results
do not prove installed workflow behavior.

Any future integration cutover is a separate reviewed change with a rollback plan
that restores website ownership; this packet does not cut over or remove the
website integration source.

Official signing, service activation, notifications, Play publication and deployment
are not authorized by a source import. Physical-device and customer acceptance
remain separate from JVM, Robolectric, assembly and lint results.
