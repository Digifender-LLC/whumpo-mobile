# Initial client import

## Provenance

The initial import copies tracked files from the private `Digifender-LLC/whumpo-website`
commit `488182fa23cbc60774c9f6aa5a856b61b78209d2`, without its Git history:

- `android/`
- `tests/fixtures/mobile-v1/`
- `docs/mobile-api-v1.md`
- `docs/android/store-listing/screenshots/`

Destination-specific documentation and ignore rules are added separately. The
screenshot README is adapted to local commands rather than the old CI workflow.
The API document keeps wire shapes but omits internal planning sections and a
historical web-gate issue, and clarifies source-only verification commands.
No backend source, databases, credentials, APKs or private CI workflows are included.

## Source and test ownership

This import does **not** remove the website repository's Android tree or disable
its CI. That repository remains the integration source of truth until a separately
reviewed cutover. Coordinate changes rather than editing both copies independently.

At import review, website PR #667 remained open at
`fc1a4da1ad5e03027d4975723e9d86069a44afa3`. Its ANR process-diagnostic scripts,
tests, workflow uploads and build documentation are **not** in this snapshot.
Reconcile the final reviewed change before cutover; do not treat it as merged or
silently abandon it. No changes to imported paths were found between the pinned
source and the website main branch during import review.

## Private integration boundaries

- `android/scripts/test-worker-journey.sh` requires the private repository's
  `tests/android-local-worker.mjs`, Worker source, schema and Node dependencies.
  It is retained for provenance, not a standalone public test command. The
  API 36 path in `ci-instrumented.sh` also invokes it. Keep the real Worker
  journey in the private repository; do not substitute mocks and call it equivalent.
- `WhumpoTokens.kt` is generated by the private design-token tool. Retain the
  generated client file and coordinate token updates until a reviewed synchronization
  mechanism replaces that coupling.
- The API contract is a historical source snapshot, not a statement about live
  service availability. References to backend files and other private documents
  describe its origin; those files are intentionally absent from this repository.
- The next integration gate must record exact mobile and backend commits, consume
  the mobile checkout explicitly, and check API fixtures and token synchronization.
  No such cross-repository gate is claimed by this initial import.

## CI and release boundaries

No GitHub Actions workflows are installed by this import. Existing private gates
remain unchanged. Before independent client development and cutover, establish
unprivileged build/lint/host checks and equivalent required emulator/integration
coverage. Do not attach public PR jobs to trusted persistent runners.
Host compatibility and privileged-job isolation need separate verification.

Official signing, service activation, notifications, Play publication and deployment
are not authorized by a source import. Physical-device and customer acceptance
remain separate from JVM, Robolectric, assembly and lint results.
